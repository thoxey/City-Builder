# Balance Iteration Protocol

1. Build the TypeScript server and run the complete GUT/Vitest suites.
2. Start `early_city_baseline` with an explicitly recorded seed and action list.
3. Persist the completed trace before changing tuning values; never overwrite it.
4. Apply one coherent tuning hypothesis.
5. Replay the identical scenario, seed, and actions.
6. Run `npm run playtest:compare -- before.json after.json`.
7. Review metric/milestone deltas and the visual checkpoints; retain human
   judgment about interest, pacing, and city legibility.
8. Keep the old trace as the unchanged source baseline and record the decision.

The first production baseline location is `user://playtests/`; filenames are
immutable session ids generated by the game-side Playtest plugin.
